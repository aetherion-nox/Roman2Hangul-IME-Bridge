Roman2Hangul IME Bridge v0.2.5
=================================
本版基于 v0.2.3，只修复普通转换模式发送大写键位时 Shift 未生效的问题。

1. 新快捷键（原功能不变）
- F8：临时进入/退出 1959 文教部式独立字母模式（原 F6）。
      退出时恢复进入前的模式，包括原先“关闭”的状态。
- F9：切换 1959 文教部式 / 2000 文观部式（原 F7）。
- F10：开启/关闭普通罗马字转换（原 F8）。
- 旧 F9 提交快捷键已删除。Enter 仍然只提交当前待输入字符，
  不传递回车事件，不引发搜索或换行。
- 其余原有的输入、分音节、空格、Tab、退格及 Esc 逻辑保持原样。

2. 双辅音（F8 独立字母模式）
输入 bb → ㅃ；jj → ㅉ；dd → ㄸ；gg → ㄲ；ss → ㅆ。
这些是 1959 文教部式的转写字符组合。
程序在输入第二个相同辅音时立即输出一个独立韩文字母。
不会让韩语输入法把它们拼合为音节。
不变的例子：o→ㅗ，e→ㅔ，eo→ㅓ，oe→ㅚ，eui→ㅢ。
当某个罗马字母还是更长组合的前缀时，需等待下一字符，
或者按 Enter 提交；连字符 - 可用于分隔。

3. 提示框位置
优先使用 Windows 公开的文本插入光标（caret）坐标，
将提示框显示在输入文字处附近，不再默认跟随鼠标。
如果程序无法取得 caret，则依次采用焦点控件和活动窗口的坐标。
部分浏览器/Word/自绘输入控件可能不暴露精确文字光标位置。

运行：安装 AutoHotkey v2（https://www.autohotkey.com/），
双击 Roman2Hangul_IME.ahk，使用 Windows 韩语两套式输入法。
普通组字模式仍需要韩语 IME 处于“한”状态。
独立字母模式输入的是不参与组字的兼容韩文字母。

当前环境不能执行 AutoHotkey Windows 实机测试，已进行静态检查。


4. v0.2.4 修复：普通 1959/2000 模式的 Shift 键位
源代码 SendKeys 函数原先错误地用不区分大小写的 != 判断大写键位，
导致初声双辅音 ㄲ/ㄸ/ㅃ/ㅆ/ㅉ 以及需要 Shift 的元音都被当作小写发送。
现改用区分大小写的 !== 判断，预期让韩语 IME 收到 Shift+相应两套式按键。
1959 测试：gga→까, dda→따, bba→빠, ssa→싸, jja→짜。
2000 测试：kka→까, tta→따, ppa→빠, ssa→싸, jja→짜。
另外：yae→얘, ye→예。
独立字母模式、回车、快捷键、提示位置和解析规则均未改动。
本环境非 Windows，尚不能实机确认所有输入框中 IME 的实际表现。


5. v0.2.5 提示框位置修复（仅更改布局定位）
- 提示框优先水平对齐实际文字插入光标。
- 同时用 Windows UI Automation 获取当前焦点输入控件的真实边界。
- 提示框位于输入框下边沿外侧，留 8 像素间距，不再压住输入内容。
- 兼容传统 Win32 输入控件；在 Chrome/Edge/部分现代编辑器中优先尝试 UIA。
- 屏幕下方空间不足时，尽可能改放输入框上方以避免遮挡。
- 某些软件不开放输入光标或输入框的可访问性坐标，此时只能使用退化定位。
- F8/F9/F10、Enter、1959/2000、独立字母及 Shift 修复均保持不变。
- 尚未在 Windows 上实机执行。
